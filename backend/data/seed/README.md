# Синтетические данные Qadam AI

Каждый JSON — массив объектов в UTF-8. Набор соответствует прежнему контракту `AGENTS.md` (до main `94f1b6f`). После перехода к AI-only бэкенду эти файлы автоматически не загружаются: актуальные стартовые данные находятся в `front/src/data/seed.js`. Ниже сохранена исходная инструкция для справки.

| Файл | Количество | Назначение |
|---|---:|---|
| businesses.json | 3 | Компании для переключателя роли |
| drafts.json | 6 | Черновики разной полноты, включая `id: demo` |
| tasks.json | 5 | Опубликованные задачи всех четырёх уровней готовности |
| teams.json | 5 | Интересы, навыки, технологии; исходные баллы 0 |
| proposals.json | 5 | Три pending, один accepted, один rejected |

Все названия и контакты синтетические. Email и ссылки используют `example.com`. Ссылки — валидные URL-заглушки, а не существующие прототипы. Предзаданные решения бизнеса нужны только для отображения состояний интерфейса; они не означают автоматический выбор команд.

## Для Айгерим: загрузка

- `drafts.json`: `{id, business_id, industry, draft}`. Поле текста называется `draft`, как в API конструктора. `demo` — черновик пекарни, который создаётся заново на защите.
- `tasks.json` содержит все поля Task, кроме `rating`. `rating_history` изначально пуст.
- Перед созданием объекта Task вычислить `rating` функцией из `backend/app/services/rating.py`; при необходимости добавить начальную запись истории с `at = updated_at`.
- Не валидировать исходный объект как готовый Task до добавления рейтинга. Рейтинг не хранится в seed и не должен заполняться постоянными числами из таблицы ниже.
- `business_id`, `task_id`, `team_id` согласованы между файлами; даты — UTC ISO 8601.
- Все пять задач опубликованы, включая низкий рейтинг. В каталоге нельзя отбрасывать `draft`.
- JSON для пошаговой демонстрации находится в `docs/demo-inputs.json`, вне каталога seed, и не должен загружаться как коллекция базы.

Значения проверены отдельным расчётом по правилам документа. `rating.py` и `schemas.py` ещё отсутствуют в полученном main (`15b2ac3`), поэтому загрузка через реальный бэкенд пока не проверена.

## Для Арсена: различия с текущим фронтендом

В main `15b2ac3` интерфейс использует собственные данные в `front/src/data/seed.js`. Новые JSON пока не подключены к нему автоматически.

| Контракт AGENTS / seed | Текущий фронтенд |
|---|---|
| `task.card.*` | поля карточки в корне задачи |
| `expected_result` | `result` |
| `success_criteria` | `criteria` |
| `interaction_format` | `format` |
| `business_id` | `company` — имя из businesses |
| `created_at`, `updated_at` | `createdAt` — число |
| `task_id`, `team_id` | `taskId`, `teamId` |
| `industry: Розничная торговля` | `Ритейл` |
| `industry: Общественное питание` | `HoReCa` |
| `draft` | `text` в SEED_DRAFTS |

Текущий выбор команды начинается с `k1`, а у новых команд ID `team-*`: при подключении нужно выбрать существующий ID. Поля `owner`, `tags`, `captain`, `members` относятся к текущему представлению фронтенда и не входят в согласованную модель. Авторство задачи определяется через выбранный `business_id`, теги можно выводить из отрасли; отсутствующие личные сведения не придумывать.

Формула `front/src/lib/scoring.js` сейчас использует коэффициенты 0 / 0.35 / 0.7 / 1 и другие пороги длины. Поэтому оценки UI могут отличаться от таблицы выше. После подключения API источником рейтинга должен стать бэкенд согласно `AGENTS.md`; текущую формулу в рамках подготовки seed мы не меняли.

## Проверено

JSON читается; минимальные количества соблюдены; ID уникальны в коллекциях; ссылки между объектами разрешаются; в карточках ровно десять строковых полей; статусы допустимы; URL и даты корректны; есть все четыре уровня рейтинга. Неподтверждённых баллов за прогресс командам не начислено.
