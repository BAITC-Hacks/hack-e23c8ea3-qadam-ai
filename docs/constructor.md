# AI-конструктор Марата

Рабочая ветка: `feat/constructor`. Форматы успешных ответов API сохранены. В запросе допускается любой непустой черновик, включая «хочу денег». Сервис вызывает существующий `llm.ask_json`; приложение и обработчики ошибок — из `main.py` Айгерим.

## Границы темы и бизнес-консультант

Внутренние ответы модели теперь содержат обязательный `intent`, без дополнительного AI-вызова:

| intent | Поведение |
|---|---|
| business_task | Обычный анализ бизнес-задачи: 3–5 вопросов, затем карточка по фактам. Социальные и образовательные проекты тоже допустимы. |
| business_coaching | Желание зарабатывать/начать дело → знакомство: опыт, аудитория, её проблема, ресурсы. 3–5 вопросов в прежних полях. Если ответы раскрыли задачу, сборка разрешена; иначе 422 с предложением уточнить ответы. |
| off_topic | 422 с вежливым объяснением границ. Ни бизнес-вопросов, ни карточки. Выбранная industry не делает бессмыслицу бизнесом. |
| needs_support | 422 с бережным сообщением о поддержке. Не задаём деловые вопросы человеку, сообщившему о личном кризисе. Цитаты в описании проекта и метафоры оцениваются по контексту. |

Пример ответа вне темы: «Я помогаю с бизнес-идеями и задачами для студенческих команд. Эта тема выходит за рамки моей роли. Расскажите, чем вы занимаетесь или какую бизнес-идею хотите развить — начнём с этого».

Сообщение при личном кризисе предлагает обратиться к близкому человеку/специалисту, а при непосредственной опасности — в местную экстренную службу и не оставаться одному. Подход к поддержке сверён с [NIMH](https://www.nimh.nih.gov/health/publications/5-action-steps-to-help-someone-having-thoughts-of-suicide); приложение не ставит диагноз и не заменяет помощь специалиста. Номера служб не угадываются по языку интерфейса.

`intent` не отправляется frontend: успешные публичные поля прежние. Внутренний отказ имеет пустые вопросы/нулевую карточку и проходит отдельную проверку. Текст сообщения задаётся сервером, не берётся из произвольного ответа модели. Проверка повторяется на этапе сборки, включая новые answers (кроме исключённого из передачи контактного поля). Ошибочное/неизвестное intent вызывает максимум один повтор и затем 503; «разрешение по умолчанию» отсутствует.

Frontend сохраняет текущий шаг и ввод, показывает сообщение как ответ помощника под полем черновика или под полями ответов, до редактирования или повторного запроса. Автоматическая заглушка отключена, чтобы отказ/сбой классификации не обходился локальной генерацией. Отдельный чат или агент не добавлен: консультирование встроено в существующие вопросы.

## Анализ черновика

`POST /api/constructor/analyze`

```json
{
  "draft": "У нас небольшая пекарня, хотим сократить списания выпечки.",
  "industry": "HoReCa"
}
```

Формат успешного ответа (пример формы, а не сохранённый ответ модели):

```json
{
  "detected": {
    "need": true, "users": false, "data": false,
    "constraints": false, "result": false, "criteria": false, "contact": false
  },
  "missing": ["users", "data", "constraints", "result", "criteria", "contact"],
  "questions": [
    {"field": "data", "text": "Какие данные о списаниях доступны?"},
    {"field": "result", "text": "Какой результат должна передать команда?"},
    {"field": "criteria", "text": "Как вы проверите результат?"}
  ],
  "source": "ai"
}
```

Вопросов 3–5, поля и тексты не повторяются. При трёх и более пропущенных полях вопросы относятся к ним; если пропусков меньше, обязательны вопросы обо всех пропусках и дополнительные уточнения. Проверка структурная: она не доказывает смысловую уместность вопроса, её проверяют на эталонных примерах.

Приоритет более весомых полей задаётся в промпте. Выбор менее весомого отсутствующего поля сам по себе не вызывает повтор запроса или ошибку 503.

## Сборка карточки

`POST /api/constructor/card`

```json
{
  "draft": "У нас небольшая пекарня, хотим сократить списания выпечки.",
  "industry": "HoReCa",
  "answers": {
    "data": "Есть CSV продаж и списаний за месяц.",
    "result": "Таблица рекомендаций по количеству выпечки на следующий день.",
    "criteria": "Расчёт суммы списаний должен совпасть с ручным подсчётом.",
    "contact": "bakery-demo@example.com"
  }
}
```

Успешный ответ: `{card, warnings: string[], source: "ai"}`. В card все поля строковые: `title`, `industry`, `context`, `need`, `users`, `data`, `constraints`, `result`, `criteria`, `contact`, `format`. Неизвестное — `""`; `source` выставляет сервер. Никакой публикации или расчёта рейтинга эти эндпоинты не выполняют.

`answers` — словарь, не массив. Допустимые ключи: `need`, `users`, `data`, `constraints`, `result`, `criteria`, `contact`. Короткое название формируется по смыслу черновика, пользователь может его исправить. Формат консультаций можно сообщить в черновике или заполнить в редакторе: отдельного ключа `format` в answers текущая общая схема не принимает.

## Промпты и достоверность

- [Анализ](../backend/app/prompts/analyze.md)
- [Сборка](../backend/app/prompts/card.md)

Инструкции передаются отдельно от пользовательского JSON. Поля модели ограничены отдельными строгими схемами без defaults. Внутренняя схема карточки допускает null, который преобразуется в строковый публичный контракт. Поля contact и industry не заполняются моделью. Structured Outputs ограничивает формат, но не доказывает отсутствие выдуманных фактов: [OpenAI Docs](https://developers.openai.com/api/docs/guides/structured-outputs).

Промпты требуют сохранять сведения, не добавлять факты и отмечать противоречия. Живые прогоны выявили повторяющиеся поля вопросов, выдуманные роли пользователей и потерю условий доступа; инструкции уточнены по этим результатам. Фактические результаты и ограничения приведены ниже. Unit-тесты используют подготовленные ответы провайдера и проверяют обработку, а не интеллект модели.

## Контакты

`answers.contact` не отправляется провайдеру. Его текст сохраняется локально в contact; если ответа нет, туда попадают распознанные каналы связи из черновика. Email, телефон из 10–15 цифр, t.me-ссылка и @ник в свободных полях заменяются случайными служебными токенами. При сборке текста карточки восстанавливаются только выданные сервером токены. Новые незамаскированные контакты и неизвестные токены в ответе модели отклоняются.

Контактный ответ может содержать также график консультаций. Его целиком сохраняем в contact и предупреждаем пользователя перенести график в format через редактор; не отправляем контактный ответ модели ради разделения текста. Исходные контакты не выводятся в логах сервиса. Маскировка ограниченная, имена и все возможные формы личных сведений она не распознаёт; используйте только синтетические данные.

После исправления M1/M2 маска сервиса поддерживает также Unicode-email (`demo@пример.рф`), punycode и `%` в локальной части. Телефон — числовой кандидат с 10–15 цифрами и разделителями пробел, скобки, дефис и точка; конечная пунктуация сохраняется вне контактного токена. Маска сервиса сохраняет даты вида YYYY-MM-DD/DD-MM-YYYY и YYYY.MM.DD/DD.MM.YYYY с временем. Это распознавание распространённых форм, не полная RFC-валидация email и не анонимизация. Склеенные контакты без разделителей, нестандартная запись, имена и произвольные личные сведения требуют отдельного решения.

Поиск email больше не перебирает суффиксы слова, числовой кандидат потребляется один раз. Для повторных контактов используется словарь; восстановление и скрытие токенов выполняются одним проходом. При выключенном AI сервис возвращает 503 до маскировки. Лимиты HTTP и строк остаются задачей A1 Айгерим: эта правка их не вводит.

**Смежная незакрытая проблема:** `llm.py` повторно маскирует готовые messages своей функцией. На текущем коде она изменяет дату `2026-09-23 14:30` и квадратично обрабатывает длинную строку из `.-`. Поэтому сохранность дат и ограничение времени всей цепочки пока не подтверждены. Unicode-контакты проверены перехватом фактических messages SDK без сетевого вызова. Подробности и передача Айгерим — в [аудите](security/2026-09-23/SECURITY-AUDIT.md#исправления-марата-и-повторная-проверка).

## Ошибки и повтор

- Некорректный запрос: `422 {"error": "..."}` через общий обработчик приложения.
- ИИ выключен/не настроен: `503 {"error": "..."}` без запроса к провайдеру.
- Ошибка провайдера, JSON или семантических ограничений: один повтор (всего максимум два запроса), затем безопасное сообщение `503`.
- Фрагменты пользовательского текста/AI-ответа сервис не логирует; только операцию, номер попытки и класс ошибки.
- Отказ по теме/недостаточный контекст: 422 с подготовленным сообщением, без повторного AI-вызова после валидной классификации. UI сохраняет ввод и шаг. Автоматической заглушки нет ни при отказе, ни при сбоях.
- Тайм-аут задаёт существующий `llm.py`; в этом изменении он не менялся.

## Проверка

Из `backend/` после установки зависимостей:

```bash
.venv/bin/python -m pytest tests/test_constructor.py -q
.venv/bin/ruff check --no-cache app/services/constructor.py app/routers/constructor.py tests
```

Ruff — локальный инструмент проверки (использована версия 0.16.8); runtime-зависимости проекта не менялись. Если его нет, установите в локальное окружение: `.venv/bin/python -m pip install ruff==0.16.8`.

Проверены: публичный контракт обоих эндпоинтов; 3–5 вопросов и уникальность; соответствие missing/detected; уточнения полного описания; невалидный JSON; отсутствие провайдера; успешный и неуспешный повтор; ошибочный ввод; маскировка и восстановление контактов; блокировка выдуманного контакта и служебных токенов.

### Реальная проверка качества

[Пять примеров](../backend/tests/fixtures/constructor_cases.json): слабый, частично полный, полный, противоречивый и с синтетическими контактами. Для каждого есть критерии ручной оценки. Ключ и модель задаются локально по инструкции Айгерим; ключ не передавать в чат или командную строку.

```bash
.venv/bin/python -m tests.manual_constructor --live > /tmp/qadam-ai-review.json
```

Это до десяти реальных вызовов, до двадцати при повторах. Скрипт вызывает сначала анализ, затем сборку с заранее заготовленными ответами; он не имитирует интерактивный ответ именно на сгенерированные вопросы. После запуска сопоставьте каждый факт с исходным вводом, проверьте вопросы и предупреждения по списку review. Нужен и отдельный сквозной прогон UI.

Отдельные [пять примеров безопасности](../backend/tests/fixtures/constructor_security_cases.json) проверяют псевдосистемную инструкцию, выдуманный срок, попытку начислить баллы/опубликовать задачу, конфликт сроков и HTML. После настройки настоящего AI:

```bash
.venv/bin/python -m tests.manual_constructor --suite security --live > /tmp/qadam-ai-security-review.json
```

Лимит — тот же: до двадцати вызовов с повторами. Успешный код выхода означает только отсутствие ошибки API/валидации. Каждый пункт `review` нужно проверить вручную; JSON и самооценка модели не доказывают смысловую безопасность. Автотесты проверяют запрет дополнительных полей действий, максимум две попытки и передачу HTML как JSON-текста. Экранирование и ручное подтверждение в UI принадлежат frontend и требуют отдельной проверки.

Для проверки границ темы добавлены [девять примеров](../backend/tests/fixtures/constructor_scope_cases.json): короткое желание денег, переход от желания к реальной задаче, посторонняя тема, бессмыслица, личный кризис в черновике/ответах, цитата в задаче сервиса поддержки, метафора и попытка подменить intent.

**Остаточные смысловые замечания последнего прогона:**

- `quality/weak`: warning говорит «данных пока нет», хотя пользователь только не знает; data корректно пустое. Вопрос о пользователях выбран вместо более весомого вопроса о приёмке — приоритет весов рекомендательный.
- `quality/contacts`: локальный прототип сохранён в need/result, но constraints пустое и получает лишнее предупреждение. Перед подтверждением нужно перенести ограничение в соответствующее поле; это влияет на полноту и рейтинг.
- `scope/quoted_crisis_in_project`: анализ излишне уточняет уже названных операторов; карточка пользователей сохраняет. `scope/business_metaphor`: вопрос упоминает доступ к CRM, хотя её наличие не сообщалось; карточка CRM не выдумывает.
- Между прогонами формулировки и заполнение полей меняются. В предыдущем прогоне warning повторил предложенные для выдумки 7 дней как неподтверждённые; в последнем этой фразы нет. Одних инструкций недостаточно для доказательства отсутствия смысловых ошибок. **M3 не объявляется полностью закрытым**; остаются ручная проверка карточки и расширение набора оценок.

Проверка интерфейса: SSR подтвердил расположение сообщения поддержки ниже textarea/полей ответов, экранирование HTML и сохранение привязок голосовых кнопок. До остановки серверов реальный запрос через Vite → FastAPI → OpenAI вернул ожидаемый 422 с сообщением поддержки. Полный интерактивный браузерный сценарий и запись с настоящего микрофона в этой проверке не проходились. По просьбе Марата все локальные веб-серверы остановлены.

## Сообщение для Айгерим через Марата

По новой задаче Марата затронуты общие `schemas.py` (непустой draft вместо трёх слов), `constructorAI.js`, `useQadam.jsx`, `Builder.jsx`, одна передача prop в `App.jsx`, текст пустого ввода в переводах и `vite.config.js` (необязательный `QADAM_API_TARGET`, адрес по умолчанию прежний). Публичные успешные JSON-ответы и рейтинг не менялись. Внутренние ModelAnalysis/ModelBuild требуют intent; подменённые ответы тестов обновлены. При 422/503 ввод сохраняется, сообщение постоянно, fallback отключён по указанию Марата. `main.py`, `llm.py`, лимиты API, каталог/публикация не менялись. Сообщения в командный чат автоматически не отправлялись.
