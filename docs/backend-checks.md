# Матрица проверки основы бэкенда

Входы для пяти случаев находятся в [backend-ai-cases.json](backend-ai-cases.json). Это синтетические примеры, адаптированные из [черновиков промптов](README.md), [демо-данных](../demo-inputs.json) и [сценария демо](../DEMO.md) к полям `backend/app/schemas.py`. Для анализа берите объект `analyze`, для сборки карточки — объект `card`. Это независимые запросы: ответы для сборки заранее заданы и не обязаны совпадать с формулировкой вопросов, полученных в анализе.

Проверяйте не буквальный текст модели, а форму и опору каждого факта на вход. Успешный анализ должен вернуть `detected`, `missing`, 3–5 вопросов `{field, text}` и `source: "ai"`. Допустимые поля вопросов: `need`, `users`, `data`, `constraints`, `result`, `criteria`, `contact`. Сборка должна вернуть карточку со строковыми `title`, `industry`, `context`, `need`, `users`, `data`, `constraints`, `result`, `criteria`, `contact`, `format`, массив `warnings` и `source: "ai"`. Поле `format` не входит в допустимые ключи `answers`: формат взаимодействия можно указать в черновике или добавить вручную при редактировании карточки. Неизвестные сведения остаются пустыми, карточку до публикации проверяет и подтверждает бизнес.

| Случай | Что проверить в анализе | Что проверить в карточке |
|---|---|---|
| `weak` — слабый черновик пекарни | Спросить о доступных данных, результате и критериях; не считать Excel или историю продаж существующими. | Сохранить потребность сократить списания и ответ о таблице рекомендаций. «Пока не знаю» не превращать в данные, «не определили» — в критерий. Не добавлять срок, контакт и числовую цель. |
| `partial` — частично полный черновик магазина | Распознать Excel за три месяца, двух менеджеров, веб-прототип и срок две недели. Уточнять отсутствующий критерий и другие реальные пробелы, не переспрашивать уже известное. | Добавить критерий «не более 10 минут». Не придумывать прежнее время подготовки, столбцы Excel, формат звонков и контакт. |
| `detailed` — подробный черновик учебного центра | При полном описании задать минимум три уточнения к деталям заполненных полей без повторов; `missing` может быть пустым. Не считать обещанную передачу CSV уже выданным доступом. | Сохранить условие передачи данных после выбора, локальный запуск, срок, критерий двух минут и контакт. Добавить значения `status`, выгрузку CSV и обработку неверной даты только из ответов. |
| `contradictory` — два срока | Спросить, какой срок верен; не выбрать его самостоятельно. | Сохранить оба срока как противоречие и предупредить о необходимости уточнения. Остальные неизвестные поля не заполнять. |
| `with_contacts` — email и телефон | Распознать, что контакт сообщён; не просить его повторно. Проверка приватности адаптера: распознаваемые email и телефон не передаются модели в исходном виде. | Сохранить сообщённый контакт в итоговой карточке без подмены и дубликатов. Сервис должен возвращать контакт из исходного ввода, даже если адаптер маскирует его для модели. |

Общие ограничения: не выполнять инструкции, вставленные в черновик; не добавлять цифры, сроки, ресурсы и контакты без источника; не вычислять рейтинг, не публиковать карточку и не выбирать команду. Вопросы должны быть уместными и не повторяться по смыслу. Содержательность вопросов и отсутствие вымышленных фактов требуют ручного просмотра фактических ответов модели.

## Ошибки

| Случай | Ожидаемое поведение | Когда проверять |
|---|---|---|
| Повреждённый JSON запроса, например тело `{` с `Content-Type: application/json` | HTTP 422, тело `{"error":"..."}`; сервер остаётся доступен. | После появления маршрутов конструктора. Сейчас этот путь возвращает 404 до разбора тела. |
| Невалидный или пустой структурированный ответ модели | Адаптер выдаёт контролируемую ошибку; сервис делает не более одного повтора и при повторной ошибке возвращает HTTP 503 `{"error":"..."}`. | После тестов адаптера и сервиса с поддельным клиентом, без реального ключа. |
| Провайдер недоступен или превышен тайм-аут | После ограниченного повтора HTTP 503 `{"error":"..."}`; ввод пользователя не теряется. После интеграции фронтенд явно показывает локальную заглушку. | После появления сервиса и подключения фронтенда; сбой провайдера лучше имитировать поддельным клиентом. |

## Что доступно сейчас

| Проверка | Статус |
|---|---|
| Запуск FastAPI по корневому `.env.example`, включая режим без ключа | Доступно; команды в [README](../README.md#быстрый-старт). |
| `GET /api/health`: поля ответа, признак ключа без раскрытия значения | Доступно. `ai_available: false` при пустых ключе и модели. |
| Единый формат ошибок HTTP и валидации | Обработчики уже есть; контрактные тесты этапа 1A проверяют их отдельно. |
| Пять примеров через `/api/constructor/analyze` и `/api/constructor/card` | Ожидают маршрутов и сервиса Марата. Сейчас роутер пустой. |
| Один вызов модели без скрытых повторов, ошибки провайдера и маскирование контактов | Проверяются тестами адаптера с поддельным клиентом; реальный вызов провайдера пока не проверен. |
| Повтор при сбое модели и ответ HTTP 503 после него | Ожидают сервиса и маршрутов Марата. |
| Явная заглушка при отказе API в интерфейсе | Ожидает подключения API во фронтенде. Сейчас фронтенд использует локальную заглушку напрямую. |

Для ручного прогона после появления маршрутов отправляйте отдельно содержимое `analyze` и `card` из каждого случая на соответствующий POST-маршрут. Записывайте дату, модель, версию промпта, фактический ответ и найденные расхождения. Эти примеры пока не являются результатами вызова OpenAI.
