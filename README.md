# Qadam AI

MVP для кейса AI Sana «Геймификация практических заданий». Бизнес с помощью ИИ превращает черновик задачи в полную карточку, получает рейтинг готовности от 0 до 100 и публикует задачу в каталоге. Студенческие команды откликаются на задачи, а бизнес сам выбирает, с кем работать.

## Быстрый старт

Нужны Python 3.11+ и Node.js. Команды ниже запускаются из корня репозитория, если перед ними не указан `cd`.

### 1. Переменные окружения

```bash
cp .env.example .env
```

Шаблон `.env.example` содержит только настройки окружения, без ключа. Для проверки локальной заглушки оставьте `OPENAI_API_KEY` и `OPENAI_MODEL` пустыми. Для вызова OpenAI впишите ключ и имя модели с поддержкой Structured Outputs только в локальный `.env`; этот файл исключён из Git.

| Переменная | Что указать |
|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI API; пустая строка означает отсутствие ключа |
| `OPENAI_MODEL` | Имя модели для конструктора; пустая строка отключает его ИИ, но не голосовой ввод |
| `AI_MODE` | `auto` — конструктор использует ключ и модель, Whisper — ключ; `stub` — ИИ и распознавание голоса выключены на бэкенде |

Без ключа сервер запускается и отвечает на `/api/health`. Фронтенд отправляет запросы к двум маршрутам конструктора и при их недоступности включает локальную заглушку (`front/src/lib/ai.js`). Ключ во фронтенд не передаётся.

### 2. Бэкенд

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

Если установлен Python 3.11 вместо 3.12, замените `python3.12` на `python3.11`. Проверьте запущенный сервер в другом терминале:

```bash
curl -i http://localhost:8000/api/health
```

Ожидается HTTP 200 и JSON с полями `ok`, `ai_mode`, `ai_available`, `openai_key`, `model`. При пустых ключе и модели и `AI_MODE=auto` значения — `true`, `"auto"`, `false`, `false`, `""` соответственно. `openai_key` — только признак наличия ключа, сам ключ в ответ не попадает. `ai_available` показывает готовность настроек, а не результат сетевого вызова к провайдеру. Документация текущих маршрутов: http://localhost:8000/docs.

Маршруты `/api/constructor/analyze` и `/api/constructor/card` реализованы по схемам из `backend/app/schemas.py`. Без настроенного ИИ они возвращают контролируемую ошибку `503 {"error":"..."}`; фронтенд переключается на локальную заглушку.

### 3. Фронтенд

```bash
cd front
npm install
npm run dev
```

Приложение: http://localhost:5173. Vite пересылает относительные запросы `/api/...` на `http://localhost:8000`. Если бэкенд не запущен, конструктор всё равно проходит шаги вопросов и карточки с видимым источником «локальная заглушка».

### Тема интерфейса

Светлая, тёмная и системная темы выбираются в боковой панели; на узком экране выбор находится в меню языка. Системная тема следует настройке устройства, в том числе при её изменении. При первом открытии используется светлая тема. Выбор (`light`, `dark` или `system`) сохраняется отдельно в `localStorage` (`qadam.theme`) и не сбрасывает задачи, черновик или язык. При недоступном хранилище переключение работает до перезагрузки. Тема применяется до загрузки React, включая фон страницы и цвет панели браузера. В группе выбора работают Tab, стрелки и пробел.

### Голосовой ввод черновика и ответов

На первом шаге конструктора нажмите «Ввести голосом», разрешите браузеру доступ к микрофону и продиктуйте задачу. Кнопка «Остановить и распознать» отправляет запись в OpenAI Whisper; через 60 секунд запись останавливается автоматически и тоже отправляется на распознавание. «Отмена» завершает запись или ожидание без добавления текста; уже отправленное аудио отозвать из внешнего сервиса нельзя. Распознанный текст добавляется к существующему черновику: проверьте и отредактируйте его, затем отдельно запустите анализ задачи.

На шаге уточнения под каждым вопросом есть кнопка «Ответить голосом». Текст дописывается только к выбранному ответу, сохраняя ручные правки и остальные ответы. Одновременно доступна одна запись или расшифровка; до её завершения или отмены другие микрофоны и сборка карточки отключены. Ручной ввод остаётся доступным.

При скрытии или закрытии вкладки, уходе с экрана записи, смене компании либо сбросе конструктора запись или ожидание отменяются; поздний результат не добавляется в другой черновик или ответ.

Нужны запущенный бэкенд, `AI_MODE=auto`, `OPENAI_API_KEY` и браузер с `MediaRecorder` на HTTPS или `localhost`. Используется модель `whisper-1`, независимо от `OPENAI_MODEL`; дополнительные зависимости не нужны. При недоступном микрофоне, сервере или Whisper остаётся ручной ввод. Голосовой заглушки нет.

Для демонстрации диктуйте только синтетические сведения. Контакты внутри аудио до отправки распознающему сервису не маскируются. Приложение держит аудио только в памяти браузера и сервера, не сохраняет его в файлы или `localStorage`; после остановки запись передаётся в OpenAI. Полученный текст становится обычным черновиком и сохраняется существующим механизмом `qadam.session`.

Контракт: `POST /api/voice/transcribe` принимает сырое аудио в теле запроса (не JSON и не multipart) с `Content-Type: audio/webm`, `audio/mp4`, `audio/wav`, `audio/x-wav` или `audio/mpeg`. Максимум — 5 МиБ (5 242 880 байт). Успех: `{"text": "распознанный текст"}`; ошибка: `{"error": "описание", "code": "код ошибки"}` со статусом 4xx/5xx. Один вызов Whisper ограничен 20 секундами без автоматических повторов; фронтенд ожидает до 30 секунд. [Документация OpenAI по распознаванию речи](https://developers.openai.com/api/docs/guides/speech-to-text).

## Архитектура

Фронтенд хранит задачи, отклики, рейтинг и состояние сценария в браузере. Бэкенд предоставляет `/api/health`, два маршрута конструктора и `/api/voice/transcribe`, но не хранит карточки в базе. Клиент вызывает анализ черновика, сборку карточки и распознавание аудио; запросы к OpenAI остаются только на бэкенде.

## Формула рейтинга

Рейтинг показывает, насколько задача готова к работе со студентами, а не насколько известна компания. Он считается детерминированно, без ИИ, в `front/src/lib/scoring.js` (`scoreCard`) и пересчитывается при каждом изменении карточки в конструкторе — ответах на вопросы и правках полей до публикации. Опубликованная задача показывается с рейтингом, посчитанным по той же формуле; редактирования после публикации в MVP нет.

**Качество поля** зависит от числа слов:

| Заполнено | Качество |
|---|---|
| пусто | 0 |
| 1–3 слова | 0,35 |
| 4–9 слов | 0,7 |
| 10 слов и больше | 1 |

**Баллы показателя = вес × качество**, с округлением. Сумма весов — 100.

| Показатель | Вес | Поля карточки | Особое правило |
|---|---|---|---|
| Контекст и потребность | 20 | `context`, `need` | среднее качества двух полей |
| Данные и материалы | 20 | `data` | |
| Ожидаемый результат | 15 | `result` | |
| Критерии успеха | 15 | `criteria` | без цифр качество не выше 0,6 |
| Ограничения | 10 | `constraints` | |
| Пользователи | 10 | `users` | |
| Связь с бизнесом | 10 | `contact`, `format` | 0,6 × `contact` + 0,4 × `format`; `contact` без email, телефона или мессенджера — не выше 0,5 |

`title` баллов не даёт, но без него задачу нельзя опубликовать.

**Уровни готовности**

| Баллы | Уровень | Что это значит |
|---|---|---|
| 0–39 | Черновик | задача видна в каталоге с пометкой «Требует уточнения», откликаться можно |
| 40–69 | Рабочая | можно откликаться, задача попадает в рекомендации |
| 70–89 | Готовая | повышенная позиция в каталоге |
| 90–100 | Приоритетная | полностью готова, выделена в каталоге |

**Прозрачность для бизнеса**: панель рейтинга показывает баллы по каждому показателю (`14/20`), список «Что поднимет рейтинг» с приростом «+N» по каждому недостающему полю, лесенку уровней и график «было → стало» (черновик → ответы → публикация).

Стартовые задачи в `front/src/data/seed.js` покрывают все уровни: 98 (Приоритетная), 88 и 78 (Готовая), 48 (Рабочая), 21 (Черновик).

## Правила каталога

Каталог и отклики работают в браузере (`front/src/store/useQadam.jsx`). Правила вынесены в чистые функции `front/src/lib/catalog.js` и покрыты тестами.

- **Кто виден.** Все опубликованные задачи любого уровня. Низкий рейтинг не скрывает задачу и не запрещает отклик.
- **Порядок.** По рейтингу по убыванию, при равенстве выше более новая задача (`rankTasks`). Позиция `#N` считается по всему каталогу и не зависит от фильтров. После публикации бизнес видит «Опубликовано · позиция #N».
- **Фильтры.** Тема (отрасль), уровень готовности и поиск по названию, компании и контексту (`filterCatalog`).
- **Рекомендации команде.** Задачи с рейтингом от 40, у которых теги совпадают с навыками команды или отрасль — с её интересами; до 3 штук, сначала с большим числом совпадений (`recommendTasks`). Рекомендации показаны над каталогом и ничего в нём не скрывают.
- **Отклик.** Любая команда может откликнуться на любую задачу, число откликов на задачу не ограничено. Одна команда — один отклик на задачу. Обязательны идея, план, срок и ссылка на прототип вида `http(s)://домен…` (`validateProposal`, `addProposal`). Ошибки показываются под полями.
- **Решение бизнеса — только вручную.** Каждый отклик приходит со статусом «На рассмотрении». Бизнес нажимает «Выбрать» или «Отклонить»; можно выбрать одну, несколько команд или никого, а отклонённый отклик вернуть на рассмотрение (`decideProposal`). Автоматического назначения нет.
- **Результат (шаг 8).** У выбранной команды бизнес подтверждает этап — команда получает **+50 баллов** (`MILESTONE_POINTS`). Повторно за тот же отклик баллы не начисляются, а решение по отклику после этого не меняется (`confirmMilestone`).
- **Сохранение.** Задачи, отклики, баллы команд и подтверждённые этапы хранятся в `localStorage` (`qadam.session`), поэтому перезагрузка страницы не сбрасывает демо. Если сохранение повреждено или устарело (другая `version`), подставляются стартовые данные. Кнопка «Сбросить демо» очищает сохранение.

## ИИ-функция

Два эндпоинта: `POST /api/constructor/analyze` (3–5 уточняющих вопросов) и `POST /api/constructor/card` (редактируемая карточка). Промпты находятся в `backend/app/prompts/`, сервис — в `backend/app/services/constructor.py`. Публичные форматы соответствуют `backend/app/schemas.py`.

ИИ-ответ проходит строгую проверку схемы и вопросов; при ошибке выполняется один повтор, затем возвращается `503 {"error": "..."}` для перехода UI на заглушку. Контактный ответ сохраняется локально; распознаваемые контакты в свободном тексте маскируются перед передачей модели. Неизвестные поля публичной карточки остаются пустыми. Подтверждение и публикацию выполняет человек во фронтенде.

[Форматы запросов/ответов, промпты, ошибки, проверки и ограничения](docs/constructor.md). [План Марата](docs/marat-roadmap.md). Реальная модель и полный UI-сценарий пока не проверены; автоматические тесты используют подменённые ответы провайдера.

## API

Клиент отправляет один JSON-запрос `POST /api/constructor/analyze` с `{draft, industry}` и ожидает `{detected, missing, questions: [{field, text}], source: "ai"}`. Затем он отправляет `POST /api/constructor/card` с `{draft, industry, answers}` и ожидает `{card, warnings, source: "ai"}`. Все 11 полей `card` — строки. Черновик должен содержать не меньше трёх слов. Тайм-аут каждого запроса — 45 секунд с учётом двух возможных попыток бэкенда.

Перед показом ответа фронтенд проверяет состав полей, типы, согласованность `detected` и `missing`, число и уникальность вопросов. Сетевой сбой, 404/503, тайм-аут и некорректный ответ включают заглушку с `source: "stub"`. HTTP 422 показывает ошибку ввода, сохраняя черновик и ответы без перехода на заглушку. Вопросы ИИ показываются как пришли с сервера; локальные вопросы берутся из переводов. Карточка остаётся редактируемой, предупреждения видны до подтверждения, публикацию запускает только бизнес.

Оба POST-маршрута реализованы; живые ответы через Vite-прокси проверены. Для локальной проверки цепочки Vite → API → интерфейс без ключа можно остановить бэкенд и запустить тестовый сервер вместо него:

```bash
cd front
node tests/mock-api.mjs
# в другом терминале: npm run dev
```

Тестовый сервер отдаёт ответы с `source: "ai"`, вопросами с пометкой `МОК:` и предупреждением в карточке. Он не обращается к OpenAI. Для проверки сбоев перезапустите его с `MOCK_AI_MODE=503`, `invalid`, `timeout` или `422`; для проверки отсутствующего API остановите сервер. При `timeout` фронтенд ждёт до 45 секунд.

Клиентские проверки без дополнительных зависимостей:

```bash
cd front
npm test
npm run lint
npm run build
```

## Тестовые сценарии

Для локальной проверки конструктора откройте приложение с тестовым сервером и введите «Нужен бот для записи клиентов в салон». Ответьте на вопросы `МОК:`, например укажите потребность «Автоматизировать запись клиентов» и данные «Таблица записей в Excel». Соберите карточку и проверьте предупреждение. Вернитесь к вопросам и черновику: пока черновик не менялся, ответы доступны. После изменения черновика запустите анализ снова. Исправьте карточку, подтвердите её и опубликуйте отдельным нажатием. Повторите без сервера: должны появиться подписи локальной заглушки, а введённые черновик и ответы сохранятся. В режиме `422` шаг остаётся прежним и показывается ошибка ввода.
