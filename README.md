# Qadam AI

MVP для кейса AI Sana «Геймификация практических заданий». Бизнес с помощью ИИ превращает черновик задачи в полную карточку, получает рейтинг готовности от 0 до 100 и публикует задачу в каталоге. Студенческие команды откликаются на задачи, а бизнес сам выбирает, с кем работать.

## Материалы команды

- [Тестовые данные](seed/README.md)

## Быстрый старт

Нужны Python 3.11+ и Node.js. Команды ниже запускаются из корня репозитория, если перед ними не указан `cd`.

### 1. Переменные окружения

```bash
cp .env.example .env
```

Шаблон `.env.example` содержит только настройки окружения, без ключа. Для проверки локальной заглушки оставьте `OPENAI_API_KEY` и `OPENAI_MODEL` пустыми. Для вызова OpenAI впишите ключ и имя модели с поддержкой Structured Outputs только в локальный `.env`; этот файл исключён из Git.

| Переменная | Что указать |
|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI API; пустая строка означает отсутствие ключа |
| `OPENAI_MODEL` | Имя модели; пустая строка означает, что ИИ недоступен |
| `AI_MODE` | `auto` — ИИ доступен при наличии ключа и модели; `stub` — ИИ выключен на бэкенде |

Без ключа сервер запускается и отвечает на `/api/health`. Фронтенд отправляет запросы к двум маршрутам конструктора и при их недоступности включает локальную заглушку (`front/src/lib/ai.js`). Ключ во фронтенд не передаётся.

### 2. Бэкенд

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

Если установлен Python 3.11 вместо 3.12, замените `python3.12` на `python3.11`. Проверьте запущенный сервер в другом терминале:

```bash
curl -i http://localhost:8000/api/health
```

Ожидается HTTP 200 и JSON с полями `ok`, `ai_mode`, `ai_available`, `openai_key`, `model`. При пустых ключе и модели и `AI_MODE=auto` значения — `true`, `"auto"`, `false`, `false`, `""` соответственно. `openai_key` — только признак наличия ключа, сам ключ в ответ не попадает. `ai_available` показывает готовность настроек, а не результат сетевого вызова к провайдеру. Документация текущих маршрутов: http://localhost:8000/docs.

Маршруты `/api/constructor/analyze` и `/api/constructor/card` пока не реализованы: роутер подключён, но пуст. Вызов сейчас возвращает HTTP 404 `{"error":"Not Found"}`. После реализации Маратом они будут использовать схемы из `backend/app/schemas.py`; пока `/docs` показывает только доступные маршруты.

### 3. Фронтенд

```bash
cd front
npm install
npm run dev
```

Приложение: http://localhost:5173. Vite пересылает относительные запросы `/api/...` на `http://localhost:8000`. Если бэкенд не запущен, конструктор всё равно проходит шаги вопросов и карточки с видимым источником «локальная заглушка».

## Структура

```
front/src/
  store/useQadam.jsx  # состояние приложения: задачи, отклики, команды
  lib/scoring.js      # формула рейтинга
  lib/api.js          # HTTP-клиент конструктора
  lib/constructorAI.js # проверка ответа и переход на заглушку
  lib/ai.js           # локальная заглушка ИИ, если бэкенд недоступен
  data/seed.js        # стартовые данные
  features/           # конструктор, каталог, отклики
backend/app/
  main.py             # приложение и единый формат ошибок {"error": "..."}
  schemas.py          # форматы API конструктора
  llm.py              # вызовы OpenAI
  routers/            # эндпоинты
  services/           # логика конструктора
  prompts/            # промпты
```

Данные и рейтинг живут во фронтенде. Бэкенд отвечает только за ИИ: анализ черновика и сборку карточки.

## Проверка основы бэкенда

Из каталога `backend/`, с активным виртуальным окружением установите зависимости для проверок и запустите их:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
python -m ruff check app tests
```

Единственная дополнительная зависимость для проверок — Ruff; при обычном запуске достаточно `requirements.txt`.

Ручные примеры и матрица ожидаемого поведения: [docs/backend-checks.md](docs/backend-checks.md), [машиночитаемые входы](docs/backend-ai-cases.json). Сейчас проверяются запуск, `/api/health`, отсутствие ключа в ответе и формат HTTP-ошибок. ## Архитектура

Фронтенд хранит задачи, отклики, рейтинг и состояние сценария в браузере. Бэкенд предоставляет HTTP API для ИИ и не хранит карточки в базе. Клиент уже вызывает маршруты анализа черновика и сборки карточки; сами маршруты пока пусты и отвечают 404. Вызовы OpenAI будут выполняться только на бэкенде.

## Формула рейтинга

_Заполнить: веса показателей, баллы за поле, уровни готовности._

## Правила каталога

_Заполнить: что видно в каталоге, сортировка, фильтры, рекомендации._

## ИИ-функция

_Заполнить: промпты, формат входа и выхода, обработка некорректного ответа, заглушка._

## API

Клиент отправляет один JSON-запрос `POST /api/constructor/analyze` с `{draft, industry}` и ожидает `{detected, missing, questions: [{field, text}], source: "ai"}`. Затем он отправляет `POST /api/constructor/card` с `{draft, industry, answers}` и ожидает `{card, warnings, source: "ai"}`. Все 11 полей `card` — строки. Черновик должен содержать не меньше трёх слов. Тайм-аут каждого запроса — 45 секунд с учётом двух возможных попыток бэкенда.

Перед показом ответа фронтенд проверяет состав полей, типы, согласованность `detected` и `missing`, число и уникальность вопросов. Сетевой сбой, 404/503, тайм-аут и некорректный ответ включают заглушку с `source: "stub"`. HTTP 422 показывает ошибку ввода, сохраняя черновик и ответы без перехода на заглушку. Вопросы ИИ показываются как пришли с сервера; локальные вопросы берутся из переводов. Карточка остаётся редактируемой, предупреждения видны до подтверждения, публикацию запускает только бизнес.

Текущий бэкенд пока не реализует два POST-маршрута, поэтому живой режим OpenAI ещё не проверен. Для локальной проверки цепочки Vite → API → интерфейс можно запустить тестовый сервер вместо бэкенда:
```bash
cd front
node tests/mock-api.mjs
# в другом терминале: npm run dev
```

Тестовый сервер отдаёт ответы с `source: "ai"`, вопросами с пометкой `МОК:` и предупреждением в карточке. Он не обращается к OpenAI. Для проверки сбоев перезапустите его с `MOCK_AI_MODE=503`, `invalid`, `timeout` или `422`; для проверки отсутствующего API остановите сервер. При `timeout` фронтенд ждёт до 45 секунд.

Клиентские проверки без дополнительных зависимостей:

```bash
cd front
node --test tests/*.test.js
npm run lint
npm run build
```

## Тестовые сценарии

Для локальной проверки конструктора откройте приложение с тестовым сервером и введите «Нужен бот для записи клиентов в салон». Ответьте на вопросы `МОК:`, например укажите потребность «Автоматизировать запись клиентов» и данные «Таблица записей в Excel». Соберите карточку и проверьте предупреждение. Вернитесь к вопросам и черновику: пока черновик не менялся, ответы доступны. После изменения черновика запустите анализ снова. Исправьте карточку, подтвердите её и опубликуйте отдельным нажатием. Повторите без сервера: должны появиться подписи локальной заглушки, а введённые черновик и ответы сохранятся. В режиме `422` шаг остаётся прежним и показывается ошибка ввода.
