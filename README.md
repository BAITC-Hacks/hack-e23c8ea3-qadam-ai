# Qadam AI

MVP для кейса AI Sana «Геймификация практических заданий». Бизнес с помощью ИИ превращает черновик задачи в полную карточку, получает рейтинг готовности от 0 до 100 и публикует задачу в каталоге. Студенческие команды откликаются на задачи, а бизнес сам выбирает, с кем работать.

## Материалы команды

- [Тестовые данные](seed/README.md)
- [Демо-сценарий и ответы](DEMO.md) и [JSON для демо](demo-inputs.json)

Данные, демо и промпты сохраняют прежний контракт и помечены как материалы для адаптации; текущее приложение использует данные из `front/src/data/seed.js`.

## Быстрый старт

Нужны Python 3.11+ и Node.js.

### 1. Переменные окружения

```bash
cp .env.example .env
```

Заполните `.env`:

| Переменная | Что указать |
|---|---|
| `OPENAI_API_KEY` | ключ OpenAI API |
| `OPENAI_MODEL` | модель с поддержкой Structured Outputs |
| `AI_MODE` | `auto` — OpenAI, если заданы ключ и модель, иначе заглушка; `stub` — всегда заглушка |

### 2. Бэкенд

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Проверка: http://localhost:8000/api/health. Документация API: http://localhost:8000/docs.

### 3. Фронтенд

```bash
cd front
npm install
npm run dev
```

Приложение: http://localhost:5173.

### Тема интерфейса

Светлая и тёмная темы переключаются в боковой панели; на узком экране переключатель находится в меню языка. При первом открытии используется светлая тема. Ручной выбор сохраняется отдельно в `localStorage` (`qadam.theme`) и не сбрасывает задачи, черновик или язык. При недоступном хранилище переключение работает до перезагрузки. Тема применяется до загрузки React, включая фон страницы и цвет панели браузера.

## Формула рейтинга

Рейтинг показывает, насколько задача готова к работе со студентами, а не насколько известна компания. Он считается детерминированно, без ИИ, в `front/src/lib/scoring.js` (`scoreCard`) и пересчитывается при каждом изменении карточки в конструкторе — ответах на вопросы и правках полей до публикации. Опубликованная задача показывается с рейтингом, посчитанным по той же формуле; редактирования после публикации в MVP нет.

**Качество поля** зависит от числа слов:

| Заполнено | Качество |
|---|---|
| пусто | 0 |
| 1–3 слова | 0,35 |
| 4–9 слов | 0,7 |
| 10 слов и больше | 1 |

**Баллы показателя = вес × качество**, с округлением. Сумма весов — 100.

| Показатель | Вес | Поля карточки | Особое правило |
|---|---|---|---|
| Контекст и потребность | 20 | `context`, `need` | среднее качества двух полей |
| Данные и материалы | 20 | `data` | |
| Ожидаемый результат | 15 | `result` | |
| Критерии успеха | 15 | `criteria` | без цифр качество не выше 0,6 |
| Ограничения | 10 | `constraints` | |
| Пользователи | 10 | `users` | |
| Связь с бизнесом | 10 | `contact`, `format` | 0,6 × `contact` + 0,4 × `format`; `contact` без email, телефона или мессенджера — не выше 0,5 |

`title` баллов не даёт, но без него задачу нельзя опубликовать.

**Уровни готовности**

| Баллы | Уровень | Что это значит |
|---|---|---|
| 0–39 | Черновик | задача видна в каталоге с пометкой «Требует уточнения», откликаться можно |
| 40–69 | Рабочая | можно откликаться, задача попадает в рекомендации |
| 70–89 | Готовая | повышенная позиция в каталоге |
| 90–100 | Приоритетная | полностью готова, выделена в каталоге |

**Прозрачность для бизнеса**: панель рейтинга показывает баллы по каждому показателю (`14/20`), список «Что поднимет рейтинг» с приростом «+N» по каждому недостающему полю, лесенку уровней и график «было → стало» (черновик → ответы → публикация).

Стартовые задачи в `front/src/data/seed.js` покрывают все уровни: 98 (Приоритетная), 88 и 78 (Готовая), 48 (Рабочая), 21 (Черновик).

## Правила каталога

Каталог и отклики работают в браузере (`front/src/store/useQadam.jsx`). Правила вынесены в чистые функции `front/src/lib/catalog.js` и покрыты тестами.

- **Кто виден.** Все опубликованные задачи любого уровня. Низкий рейтинг не скрывает задачу и не запрещает отклик.
- **Порядок.** По рейтингу по убыванию, при равенстве выше более новая задача (`rankTasks`). Позиция `#N` считается по всему каталогу и не зависит от фильтров. После публикации бизнес видит «Опубликовано · позиция #N».
- **Фильтры.** Тема (отрасль), уровень готовности и поиск по названию, компании и контексту (`filterCatalog`).
- **Рекомендации команде.** Задачи с рейтингом от 40, у которых теги совпадают с навыками команды или отрасль — с её интересами; до 3 штук, сначала с большим числом совпадений (`recommendTasks`). Рекомендации показаны над каталогом и ничего в нём не скрывают.
- **Отклик.** Любая команда может откликнуться на любую задачу, число откликов на задачу не ограничено. Одна команда — один отклик на задачу. Обязательны идея, план, срок и ссылка на прототип вида `http(s)://домен…` (`validateProposal`, `addProposal`). Ошибки показываются под полями.
- **Решение бизнеса — только вручную.** Каждый отклик приходит со статусом «На рассмотрении». Бизнес нажимает «Выбрать» или «Отклонить»; можно выбрать одну, несколько команд или никого, а отклонённый отклик вернуть на рассмотрение (`decideProposal`). Автоматического назначения нет.
- **Результат (шаг 8).** У выбранной команды бизнес подтверждает этап — команда получает **+50 баллов** (`MILESTONE_POINTS`). Повторно за тот же отклик баллы не начисляются, а решение по отклику после этого не меняется (`confirmMilestone`).
- **Сохранение.** Задачи, отклики, баллы команд и подтверждённые этапы хранятся в `localStorage` (`qadam.session`), поэтому перезагрузка страницы не сбрасывает демо. Если сохранение повреждено или устарело (другая `version`), подставляются стартовые данные. Кнопка «Сбросить демо» очищает сохранение.

## ИИ-функция

Два эндпоинта: `POST /api/constructor/analyze` (3–5 уточняющих вопросов) и `POST /api/constructor/card` (редактируемая карточка). Промпты находятся в `backend/app/prompts/`, сервис — в `backend/app/services/constructor.py`. Публичные форматы соответствуют `backend/app/schemas.py`.

ИИ-ответ проходит строгую проверку схемы и вопросов; при ошибке выполняется один повтор, затем возвращается `503 {"error": "..."}` для перехода UI на заглушку. Контактный ответ сохраняется локально; распознаваемые контакты в свободном тексте маскируются перед передачей модели. Неизвестные поля публичной карточки остаются пустыми. Подтверждение и публикацию выполняет человек во фронтенде.

[Форматы запросов/ответов, промпты, ошибки, проверки и ограничения](docs/constructor.md). [План Марата](docs/marat-roadmap.md). Реальная модель и полный UI-сценарий пока не проверены; автоматические тесты используют подменённые ответы провайдера.
