# Решения Qadam AI

## 2026-09-23 14:25 (Asia/Almaty) — контракт этапа 0

- **Решение:** сохраняем React/Vite во фронтенде и FastAPI/Pydantic/OpenAI на бэкенде; бэкенд отвечает только за ИИ. **Причина:** это действующий стек и разделение ответственности в `AGENTS.md`; предложение Streamlit/SQLite в `Codex.md` относится к пустому проекту. **Контракт:** данные, рейтинг, каталог и отклики остаются во фронтенде. Упомянутое в плане прежнее решение о JSON-хранилище расходится с текущим `AGENTS.md`; вопрос отложен до отдельного этапа, без изменения хранения сейчас.
- **Решение:** сохраняем публичные схемы `backend/app/schemas.py` без переименований. **Причина:** они совпадают с `EMPTY_CARD` в `front/src/data/seed.js`, `QUESTION_BANK` в `front/src/lib/ai.js` и API в `AGENTS.md`. **Контракт:** `Card` содержит строковые `title`, `industry`, `context`, `need`, `users`, `data`, `constraints`, `result`, `criteria`, `contact`, `format`; поля вопросов — `need`, `users`, `data`, `constraints`, `result`, `criteria`, `contact`. Черновик — минимум 3 слова. `industry` в запросах по текущей схеме допускает пустую строку; `answers` обязателен для сборки карточки.
- **Решение:** оставляем форматы HTTP: `GET /api/health` → `{ok, ai_mode, ai_available, openai_key, model}` (`openai_key` — признак наличия, не ключ); `POST /api/constructor/analyze` с `{draft, industry}` → `{detected, missing, questions: [{field, text}], source: "ai"}`; `POST /api/constructor/card` с `{draft, industry, answers}` → `{card, warnings, source: "ai"}`. Ошибки — `{"error": str}` со статусом 4xx/5xx; `source` допускает `"ai" | "stub"` для общего контракта с фронтендом. **Причина:** эти формы уже определены в `AGENTS.md` и Pydantic; успешный ответ бэкенда помечается `"ai"`, локальная заглушка фронтенда — `"stub"`. **Контракт:** потребители и исполнитель роутера используют эти имена и типы.
- **Решение:** `llm.ask_json` делает ровно одну попытку и возвращает типизированный Pydantic-ответ либо `LLMError`. Сервис конструктора отвечает максимум за один повтор при ошибке и за контролируемую `503`; фронтенд при недоступном или некорректном API-ответе включает явную локальную заглушку. **Причина:** исключаем вложенные повторы и сохраняем рабочий сценарий без бэкенда. **Контракт:** модели ответа LLM отдельны от публичных схем и не содержат значений по умолчанию; подтверждение и публикация карточки остаются действиями бизнеса.

## 2026-09-23 — тема интерфейса

- Решение: светлая/тёмная тема через палитру CSS и отдельный React-провайдер; начальная тема светлая. Выбор — строка `light`, `dark` или `system` в `qadam.theme`; `system` следует текущей теме устройства. Выбор оформлен нативной группой радиокнопок с управлением клавиатурой.
- Причина: единый вид всех экранов без новых зависимостей и без вмешательства в логику задач и AI.
- Контракт: добавлен только ключ настройки интерфейса; `qadam.session`, формула рейтинга и API не меняются. Недоступное хранилище не мешает переключению в текущей вкладке.

## 2026-09-23, Asia/Almaty — конструктор Марата

- Решение: сохраняем FastAPI + React и публичные модели из `backend/app/schemas.py`, реализуем сервис, роутер, промпты и тесты Марата. Причина: действующий командный контракт. Контракт: `/api/constructor/analyze` и `/api/constructor/card` без изменений полей.
- Решение: отдельные строгие модели ответа LLM живут в сервисе; обязательные строковые поля карточки допускают null внутри ответа модели, а публичная Card получает пустые строки. Причина: совместить неизвестные значения по Codex.md с существующим строковым API. Контракт с UI не меняется.
- Решение: `answers.contact` не передаётся модели; email, телефон и ссылки/ники связи в свободном тексте маскируются локально. Контакт возвращается из исходного ввода кодом, а не из догадки модели. Причина: Codex.md §7. Остальной текст проходит ограниченную локальную маскировку, которая не гарантирует удаления всех персональных данных.
- Решение: при выключенном AI сразу 503; при ошибке провайдера или проверке ответа максимум две попытки, затем 503. Заглушка остаётся на фронтенде. Причина: действующая архитектура AI-only бэкенда. В задаче 1 тайм-аут одного вызова `llm.ask_json` изменён с 30 до 20 секунд; скрытых повторов в адаптере нет.

## 2026-09-23 15:38 (Asia/Almaty) — приоритет вопросов без отказа API

- **Решение:** приоритет более весомых отсутствующих полей остаётся рекомендацией в промпте; выбор менее весомых полей сам по себе не отклоняет ответ модели. **Причина:** корректные вопросы отклонялись обеими попытками и приводили к 503 с переходом на заглушку. **Контракт:** формат `/api/constructor/analyze` не меняется; сохраняются проверки 3–5 уникальных непустых вопросов, допустимых полей, согласованности `detected`/`missing` и отсутствия контактных токенов. Регрессионный тест подтверждает 200 с первой попытки для вопросов про `users`, `data`, `constraints`, даже если `result` и `criteria` тоже отсутствуют.

## 2026-09-23 16:06 (Asia/Qyzylorda) — голосовой ввод через Whisper

- **Решение:** добавить запись черновика через браузерный `MediaRecorder` с явным запуском, остановкой и отменой; максимум 60 секунд. Распознанный текст дописывается к черновику и остаётся доступным для ручной проверки до анализа. **Причина:** ускорить ввод описания задачи, сохранив контроль человека и существующий сценарий конструктора. **Контракт:** публикация, рейтинг, модель карточки и текущие API конструктора не меняются; новые UI-тексты доступны на ru/kk/en.
- **Решение:** `POST /api/voice/transcribe` принимает сырое аудио до 5 МиБ с MIME `audio/webm`, `audio/mp4`, `audio/wav`, `audio/x-wav` или `audio/mpeg` и возвращает `{"text": str}` либо `{"error": str, "code": str}` с 4xx/5xx. **Причина:** нативная запись без новых зависимостей и отдельного файлового хранилища. **Контракт:** сервер вызывает `whisper-1` при `AI_MODE=auto` и наличии `OPENAI_API_KEY`, независимо от `OPENAI_MODEL`; тайм-аут SDK — 20 секунд без повторов, клиента — 30 секунд. При отказе остаётся ручной ввод, аудиозаглушка не используется.
- **Решение:** приложение не сохраняет аудио на диск или в `localStorage`, держит его только в памяти на время обработки и отправляет в OpenAI после остановки записи. Текст результата сохраняется как обычный черновик существующим механизмом `qadam.session`. **Причина:** не расширять хранение данных ради голосового ввода. **Контракт:** текстовая маскировка контактов не применяется к аудио до распознавания; интерфейс предупреждает не диктовать личные и чувствительные сведения, для демо используются только синтетические данные. Запись требует HTTPS или `localhost` и разрешения микрофона.
